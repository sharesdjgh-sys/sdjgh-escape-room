# 학교 계정으로 참가 신청 연결하기

지금 홈페이지에는 실제 신청서와 입력 항목이 표시됩니다. 아직 Apps Script 주소가 없으므로 미리보기이며, 개인정보는 저장하지 않습니다. 구글 설문으로 이동하는 링크는 제거했습니다.

## 1. 비공개 Google Sheets 만들기

학교 Google 계정으로 새 스프레드시트를 만들고 이름을 **서대전여고 방탈출 체험 신청 명단**으로 지정합니다. 공유는 **제한됨**으로 유지하세요. 시트를 공개하거나 웹에 게시할 필요가 없습니다.

## 2. Apps Script 파일 붙여넣기

시트에서 **확장 프로그램 → Apps Script**를 엽니다. 아래 파일을 각각 복사합니다.

| 프로젝트 파일 | Apps Script에서 만들 파일 |
| --- | --- |
| apps-script/Code.gs | 스크립트 Code.gs |
| apps-script/Index.html | HTML Index |
| apps-script/Styles.html | HTML Styles |
| apps-script/Client.html | HTML Client |

HTML 파일은 왼쪽 **+ → HTML**로 만들고 이름에는 .html을 중복 입력하지 않습니다.

프로젝트 설정에서 시간대를 **서울(Asia/Seoul)**로 설정합니다. **appsscript.json 매니페스트 파일 표시**를 켜고 이 폴더의 appsscript.json 내용으로 설정하면 필요한 권한도 명시됩니다.

Index.html, Styles.html, Client.html은 이미 생성되어 있습니다. 디자인이나 동작을 나중에 바꾸면 로컬에서 아래 명령을 실행해 다시 생성한 뒤 Apps Script에 반영하세요.

    node scripts/build-apps-script.mjs

원본은 registration/index.html, registration/form.css, registration/form.js로 분리되어 있습니다.

## 3. 초기 설정

Apps Script 편집기의 Code.gs 맨 아래에 다음 임시 함수를 추가하고 저장합니다. 상단 함수 목록에서 **initializeRegistration**을 선택해 한 번 실행하고 학교 계정으로 권한을 승인합니다.

```javascript
function initializeRegistration() {
  setup_();
}
```

전용 **신청명단** 탭과 기본 설정이 생깁니다. 기존 탭을 지우거나 초기화하지 않습니다. 성공 후에는 **추가한 initializeRegistration 함수만 삭제하고 저장한 뒤 배포**하세요. 기존 setup_ 함수는 유지합니다.

프로젝트 설정의 **스크립트 속성**에서 다음 항목을 확인합니다.

| 속성 | 설정할 내용 |
| --- | --- |
| SPREADSHEET_ID | 초기 설정이 현재 시트 ID를 자동 입력 |
| SHEET_NAME | 기본값: 신청명단 |
| SITE_ORIGIN | 실제 홈페이지 출처. 예: https://사용자명.github.io — 저장소 경로와 마지막 /는 제외 |
| PRIVACY_RETENTION_TEXT | 학교에서 확정한 개인정보 보유·이용 기간. 기본값은 비어 있음 |
| PRIVACY_VERSION | 기본값: 2026-01. 동의 안내 변경 시 버전도 변경 |
| OPEN_AT | 2026-09-28T00:00:00+09:00 |
| CLOSE_AT | 2026-10-07T16:00:00+09:00 |
| REGISTRATION_ENABLED | 준비·검증 중에는 false, 실제 운영 준비가 완료되면 true |

행사 연도는 현재 일정의 요일과 일치하는 **2026년**으로 설정했습니다. 시작 시각은 9월 28일 00:00(한국 시간)입니다. 실제 운영 조건이 다르면 수정하세요. 학교에서 개인정보 안내와 보유 기간을 확인한 후 접수를 켜세요. 보유 기간 문구를 입력하는 것만으로 자동 삭제되지는 않으며, 학교 담당자가 해당 기한에 맞춰 명단과 보관 사본을 정리해야 합니다.

필수 설정이 비어 있거나 접수 기간 밖이면 서버도 신청을 받지 않습니다. HTML에서 버튼만 활성화해도 우회할 수 없습니다.

## 4. 웹 앱 배포

**배포 → 새 배포 → 웹 앱**

- 실행 사용자: **나(학교 담당자 계정)**
- 액세스 권한: **모든 사용자**(로그인하지 않은 외부 학생도 접근 가능)

학교 관리자 정책으로 외부 접근 항목이 없으면 관리자에게 확인해야 합니다. 확인될 때까지 홈페이지의 제출 버튼은 비활성화 상태로 둡니다.

배포 완료 후 **/exec**로 끝나는 웹 앱 URL을 복사합니다. /dev 테스트 주소는 사용하지 않습니다.

## 5. 홈페이지에 주소 넣기

루트의 **registration-config.js**에서 webAppUrl을 아래 형식으로 설정합니다.

    window.ESCAPE_REGISTRATION = Object.freeze({
      webAppUrl: "https://script.google.com/macros/s/배포ID/exec"
    });

변경된 홈페이지 파일을 GitHub Pages에 반영하면 신청서가 페이지 안에서 열립니다. 이 URL은 공개되어도 되는 웹 앱 주소입니다. 스프레드시트 ID, 관리자 자격증명, OAuth 토큰은 홈페이지 파일에 넣지 않습니다.

외부 홈페이지 삽입을 위해 Apps Script는 ALLOWALL을 사용합니다. 폼은 SITE_ORIGIN으로 지정한 부모 페이지의 연결 응답을 확인한 뒤 제출을 허용합니다. 부모 페이지는 Google 출처와 일회성 채널 값을 검증하고, 높이 변경·연결 확인 메시지만 주고받습니다. 신청자 개인정보를 부모 페이지 메시지로 보내지 않습니다.

## 6. 공개 전 확인

별도의 테스트 시트와 테스트 배포에서 시작 시각을 과거, 마감 시각을 미래로 설정하고 REGISTRATION_ENABLED=true로 시험합니다. 운영 시트에는 가짜 신청을 넣지 않는 것을 권합니다.

1. 로그아웃/시크릿 창과 휴대폰에서 홈페이지 내 신청서가 열리는지 확인합니다.
2. 시험용 정보 한 건을 제출하고 시트 한 행과 화면의 접수번호가 일치하는지 확인합니다.
3. 같은 학교·학번을 다시 신청하면 중복 안내가 나오는지 확인합니다.
4. 회차마다 4명이 접수되더라도 접수가 계속 가능한지 확인합니다. **선정 인원만 최대 4명**이며 선착순 제한은 없습니다.
5. 마감/접수 중지 상태에서는 저장되지 않는지 확인합니다.
6. 운영 배포에서는 원래 접수 기간과 운영 시트 ID를 반드시 사용합니다.

현재는 자동 문자·이메일, 신청자용 조회·수정·취소, 자동 추첨, 자동 파기 기능은 포함하지 않았습니다. 연락과 선정은 담당자가 비공개 시트에서 진행합니다. 신청 변경은 담당자에게 확인하는 운영 방식입니다.

## 저장과 오류 처리

- 이름·학교·5자리 3학년 학번·010 전화번호·1~6회차·참가 자격·동의를 서버에서 검증합니다.
- 신청 시간, 접수번호, 동의문 버전, 재시도 식별자를 함께 기록합니다.
- 동시 쓰기는 잠금으로 처리하고, 동일 요청 재전송 시 원래 접수번호를 돌려줍니다.
- 학교명(공백 제거)과 학번이 같은 신청은 중복으로 처리합니다. 학교명 표기가 다르면 담당자가 추가 확인할 수 있습니다.
- 전화번호와 학번은 문자로 저장하고 수식으로 실행될 수 있는 입력은 무력화합니다.
- 실제 저장 확인 후에만 접수 완료를 표시합니다. 결과가 불확실하면 입력을 유지한 채 같은 요청으로 재확인합니다.
- 홈페이지 내 신청은 저장 성공 시 완료 팝업을 표시하며, 팝업을 닫으면 접수번호 화면으로 안내합니다. 홈페이지와 Apps Script의 Client.html을 함께 갱신해야 합니다.
- 브라우저 저장소에 신청자 개인정보를 남기지 않습니다.
- 공개 서버 함수는 신청 저장만 제공하며, 전체 명단을 읽는 기능은 제공하지 않습니다.
- 간단한 자동입력 방지 칸을 포함하지만, 인증이나 CAPTCHA를 대체하지는 않습니다.

Apps Script 내용을 변경한 뒤에는 **배포 관리 → 수정 → 새 버전 → 배포**가 필요합니다. 기존 배포를 갱신하면 홈페이지의 URL을 바꾸지 않아도 됩니다.

완료 팝업 관련 변경을 적용할 때에는 재생성된 **Client.html**을 Apps Script의 Client 파일에 복사한 뒤 위 절차로 기존 배포를 갱신하세요. 홈페이지의 index.html, style.css, script.js, registration-embed.js도 GitHub Pages에 반영해야 합니다. 접수번호는 신청서 안에만 표시하고, 부모 페이지에는 개인정보 없이 완료 여부만 전달합니다.
